# 分桶迁移工作台

设备指标的分桶口径从「本地整点」迁移到「站点营业日 + 不等长班次」的完整工作台：
规则版本管理、历史重算、新旧口径并行查询、失败段恢复、可核对的合成数据。
纯 Python 标准库实现（`zoneinfo` / `sqlite3` / `http.server`），无第三方依赖。

```
workbench/
  rules.py     规则版本与归属：时间区间 / 桶标签 / 归属规则三者分离
  storage.py   SQLite schema、写事务（单写者锁）、规则版本注册
  ingest.py    持续入仓：对所有 active 规则版本原子双写
  migrate.py   迁移引擎：分段、整桶幂等重算、失败恢复、段失效
  query.py     按口径查询 + 覆盖率报告 + 旧链接兼容层
  synth.py     确定性合成事件 + 独立暴力对账
  server.py    JSON API + 静态页 + 后台迁移 worker
web/index.html 工作台页面（原生 JS，无外部依赖）
tests/         34 个单元/集成/HTTP 冒烟测试
run_demo.py    端到端演示脚本
```

## 三个概念显式分离

| 概念 | 定义 | 落库 |
|---|---|---|
| 时间区间 (range) | 查询/迁移任务的 UTC 半开区间 `[start, end)` | jobs / segments 表 |
| 桶标签 (label) | 规则版本 + 站点时区 + UTC 瞬间的纯函数，稳定字符串 | buckets 表（标签 ↔ UTC 边界） |
| 归属规则 (attribution) | instant → bucket 的映射，按规则版本参数化 | rule_versions 表（不可变） |

- v1（旧）：`hour:2026-11-01T01:00:00-05:00` —— 标签带本地偏移。
- v2（新）：`day:2026-11-15:shift:night` —— 营业日 + 班次名。

## 关键决策：保留旧桶 + 回原始事件重算

**不重新分配旧桶。** 旧的小时聚合无法精确拆进新口径（见下节），重新分配只会
把误差藏进新数据。因此：

1. v1 聚合**原样保留、永不被改写** —— 历史查询链接（`/api/legacy/hourly?...`）
   在迁移前后返回逐字节一致的结果（有测试锁定）。
2. v2 一律**从原始事件重算**：入仓双写覆盖新版本激活之后的流量，
   分段迁移覆盖激活之前的历史。
3. 原始事件缺失的区间只标注 `unrecoverable`，**不编造精确值**。

### 旧小时汇总无法恢复的信息

- **小时内分布**：班次边界不在整点（如 13:30）时，无法把一小时拆开归到两个班次；
- **跨午夜班次的营业日归属**：需要事件级时间戳判断归开工日还是收工日；
- **min / max / 首尾事件 / 去重设备数**：旧汇总只存 count 与 sum；
- **DST 重复小时内的精确位置**：若旧系统把两个 01:00 记成一个标签，无法区分。

这些只能回到原始事件重算；事件不在，就如实标记。

## DST 与跨午夜：不加固定小时

所有边界都由「本地墙钟时间 + IANA 时区」**正向转换**为 UTC（`zoneinfo`），
绝不 `local + timedelta(hours=k)` 推算：

- spring-forward 当天营业日 23 小时、不存在的小时不产生桶；
- fall-back 当天 25 小时、重复的 01:00 按偏移分成两个桶（各 1 真实小时，首尾相接）；
- 跨午夜夜班 22:00→06:00 的真实时长：spring 当夜 **7h**、fall 当夜 **9h**、普通夜 8h
  （`tests/test_rules.py` 锁定）；
- 班次表校验必须铺满 24h（允许不等长、允许跨午夜），缺口/重叠/零长直接拒绝；
- 跨午夜归属可配：`start_day`（默认，夜班归开工日）/ `end_day`，
  并可设营业日界 `day_start`（如 04:00，凌晨开工的班归前一营业日）。

## 一致性模型：规则改版 × 持续入仓 × 历史回补并行

- **events 表是唯一事实来源**；任何口径的聚合都可由它重算。
- **入仓双写**：每条事件在同一事务内写入所有 active 规则版本的聚合；
  按 event_id 幂等（重复投递只计一次）。
- **规则不可变**：改版 = 新版本号（v3），旧版本聚合原样保留，可并行查询。
- **段重算**：段是调度/恢复单位，**桶是重算原子单位** —— 段边界可任意切，
  与段相交的桶按整桶从 events 全量重算（delete + insert 同一事务），幂等；
  跨段边界的跨午夜班次也不会算错。
- **覆盖率报告**分两层，互不掩盖：
  - 计算覆盖：`done 段 ∪ [版本激活时刻, ∞)` 未覆盖且有事件 → `pending`；
  - 数据可恢复性：区间内无原始事件但其他口径有聚合 → `unrecoverable`
    （**段「成功」跑过也不能掩盖**：零事件的重算结果不等于数据可恢复）。
- 新旧查询各自只读本口径的聚合，因此任何时刻各自读到完整一致的结果；
  未覆盖部分显式列出，绝不静默当 0。

## 失败与恢复

- 段内事件时间戳损坏 → 该段 `failed`（其余段不受影响），错误信息含事件 id；
- `POST /api/events/fix`：改正时间戳或隔离事件；**修复会自动使覆盖相关时间点的
  已完成段失效（转 pending）**——数据变了，段必须重算；
- 注意：修复落在「live 覆盖」区间（无段可失效）时，需对该区间各口径补一个
  重算任务（`run_demo.py` 第 5 步演示）；
- `POST /api/segments/{id}/retry` 重试失败/卡住的段。

## 运行

```bash
python3 -m unittest discover -s tests   # 34 个测试
python3 run_demo.py                     # 端到端演示（含失败注入与恢复）
python3 run_demo.py --serve             # 演示后启动工作台 http://127.0.0.1:8765
```

页面功能：系统状态与规则版本创建、合成数据生成/修复/对账、两口径对比
（含覆盖率与缺口）、事件归属查看器、迁移控制台（建任务/看段/重试）、
旧链接查询与不可恢复信息说明。

### API 摘要

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/state` | 站点 / 规则版本 / 任务 |
| POST | `/api/rules` | 创建规则版本（不可变，重名 409） |
| POST | `/api/ingest` | 批量入仓（全口径双写，幂等） |
| POST | `/api/synth/generate` | 合成事件 + 可选 9 月旧汇总 + 坏事件 |
| GET | `/api/synth/verify?site=&rule=` | events 独立重算 vs 聚合表对账 |
| GET | `/api/query?site=&rule=&from=&to=` | 按口径查询（缺 rule 默认 v1，历史链接语义） |
| GET | `/api/legacy/hourly?site=&date=&hour=` | 旧链接兼容（恒读 v1） |
| GET | `/api/attribute?site=&ts=` | 瞬间在各口径下的归属 |
| POST | `/api/migrations` | 创建迁移任务（分段） |
| POST | `/api/migrations/run` | 同步执行全部待办段 |
| GET | `/api/migrations?job_id=` | 任务与段状态 |
| POST | `/api/segments/{id}/retry` | 重试失败段 |
| POST | `/api/events/fix` | 修复/隔离坏事件（自动失效相关段） |

## 合成事件的可核对性

`synth.synth_events()` 用固定种子生成，含手工放置的边界案例：
spring-forward 跳变前后、fall-back 两个 01:30、班次边界 ±1 分钟、
跨午夜归属（凌晨事件归前一营业日）。`synth.verify()` 用一条独立路径
（从 events 表逐事件重算）与聚合表对账，任何不一致逐桶列出；
legacy-import 区间（无原始事件的旧仓数据）单独归类，不参与一致性判定。

## 局限（生产化方向）

- 单写者锁串行化写入，适合工作台规模；生产可换 PostgreSQL + 按桶版本号；
- 段重算按站点串行，可按站点/时间段并行；
- 班次边界恰好落在不存在的本地时刻（如 02:00 跳变日）时按 zoneinfo 的
  确定性规则解析，建议在建规则时对营运日历做边界校验；
- 查询的区间合计由页面汇总相交桶得到，未做桶裁剪加权。
